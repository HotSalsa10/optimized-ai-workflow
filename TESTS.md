# TESTS

Every check in this repo, and what runs it. What exists is not the same as what runs, so each row names its runner.

A check that has not been seen to fail is untested (M041). Every check below has planted defects in `tests/plants/dev-checks.sh` that must turn it red for its stated reason, and each check must stay green on a clean copy. Some checks also have a "looks close but is fine" case that must stay green, so a rule that fires too widely is caught too. Plants run in a throwaway copy of the repo, never in the working tree, so no plant can be left behind and no real work can be lost. Each plant that changes a file first confirms the change really landed before the check is run.

Rules every check follows:
- Text taken from a file name or file content is printed with control characters escaped (`\x0A`, `\x1B`), so a file cannot start a new line of output, move the cursor or send the CI runner a command.
- Each wrapper reads its helper's counts strictly: a count that is not one plain number is a failure, never a pass.

## Planted breaks

To check the checks, each guard added in steps 1 and 1b was removed once in a throwaway copy, and the full test suite was run against it. Every removal turned the suite red through the test written for that guard, except 2 removals that change no behaviour and so cannot be caught: the allowlist's lookup by path (the id already includes the path) and the `./` before perl file names (every name already starts with `scripts/`). Every portability rule was also deleted in turn, and each deletion was caught.

## Known limits

- The secret scan reads the working-tree copies of the tracked files and the staged copies that differ, not git history. A secret added and removed within one push is not seen. A history scan is planned for Release 2.
- The portability lint is an early warning. It reads one line at a time and treats here-doc text as code, so it can miss a form split across lines and can flag text inside a here-doc. The real proof that the scripts run on bash 3.2 and BSD tools is the test suite on macOS, and on Git Bash it is the Windows run. Both run only on release tags and by hand (decision A19), and neither has run yet (RISKS #9).
- No local bash 3.2 was available, so bash 3.2 behaviour has not been seen here.
- The secret scan misses many common credential forms. Checked misses: a quoted value under a bare TOKEN name (GITHUB_TOKEN="...", "NOTION_TOKEN": "..."), an unquoted YAML value (password: ...), a list item (- DB_PASSWORD=...), an Authorization Bearer header, a password in a URL (user:pass@host), .npmrc and .netrc entries, encryption_key, and key shapes such as sk_live_, glpat- and hf_. Closing these, and adding a second scanner, comes before the owner's files are imported (ROADMAP Track 3).
- In binary files the secret scan looks for keys and tokens, not for email addresses, phone numbers or IBANs.
- The secret scan accepts these misses so that ordinary text stays green: phone numbers written with dots (+1.415.555.0132); a phone number straight after `=` (phone=+14155550132); an IBAN run together with the next word (DE89370400440532013000BIC); UTF-16 without a byte-order mark when the text is mostly not ASCII.
- The portability lint misses an xargs `-r` that comes after an option with a quoted value (xargs -d '\n' -r). It flags every `$( )` that runs onto the next line, including valid ones.
- The rule-map check does not resolve `docs//rule-map.md` or `docs/../docs/rule-map.md` to the rule map.
- The workflow lint reads YAML line by line, so it can flag valid YAML it cannot read (a flow mapping, an anchor); write such values in block style.
- The plants that need a newline or a colon in a file name are skipped on Windows, whose file system does not allow those names.

## Where CI runs

- Linux: every push and pull request.
- Windows (Git Bash) and macOS: release tags and manual runs (decision A19).
- Each run step first sends `::stop-commands::` with a random token, so the runner reads no workflow commands from the output that follows. A manual run and a push run on the same branch use different concurrency groups, so neither cancels the other.

## Running locally

```
bash scripts/dev/validate.sh
bash tests/run.sh
```
