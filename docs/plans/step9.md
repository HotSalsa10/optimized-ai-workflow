**S4. Code Mode stays off (M165; needed in step 8).** Measured: not a path around the guard. **S7. The project CI template (9.3, M166).** `method/scripts/method/templates/method-checks.yml.tmpl`, at the top of `templates/` like the pull request template. setup-write seeds it as `.github/workflows/method-checks.yml` (class S: written only when absent, never overwritten). It:
- runs on `push` to every branch and on `workflow_dispatch`, and on nothing else; no `pull_request` trigger, for A76's reasons (a push run already checks the head, and a pull request run judges GitHub's test merge commit, not the head), and no `pull_request_target`, `workflow_run` or comment trigger;
- reads no secret and no `github.token`; sets `permissions: contents: read`, a timeout, `persist-credentials: false`, and the stop-commands line in each step, as this repo's ci.yml does;
- pins `actions/checkout` to the same commit as ci.yml (a test holds the two equal, one value in two files);
- runs `CI=true bash scripts/method/run-checks.sh`, which runs the built-in checks (`method-files` and `secrets` among them) and every project row that runs in CI; a marked, commented place holds the project's own set-up steps, such as installing a dependency scanner the checks file turns on (M094's CI part), and says that a tool installed there names an exact version and that each step keeps the stop-commands line;
- says in a comment, and the setup card says too, that the run is red with exit 3 when nothing failed but a check that applies was skipped or no project check runs in CI (F25), and how to fix that: install the tool the skipped row needs in the set-up place, or mark the row local.
It is project-owned, since only the project knows its own set-up steps, and it sits on the built-in steering list (`.github/workflows`, M153), so a change to it takes the full route with three reviewers. Once seeded nothing in the project lints it: that review is its only lock (section 5). Rejected: installing it by sync as a method file (`@DIRS` would gain a file in a folder GitHub reads only flat, and a project could not add its set-up steps); a done-check job (done-check reads receipts, which a CI clone does not have; Release 2, S8); a `pull_request` trigger (A76).
