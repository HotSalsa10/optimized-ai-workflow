- Source checks: sync's own. The release checkout must be clean, at an exact `v*` tag, with perl and JSON::PP. That checkout's tag may differ from the project's: uninstall reads only the project's own `method.lock`, its installed `settings.method.json` and its `profiles.tsv`, and first checks all three against the lock, through the checkout's `lib/lock.pl`. The lock format is unchanged since v0.7.0.
- The before commit: the first parent of the newest commit that added `scripts/method/method.lock` (`git log --diff-filter=A -1`), read with `git cat-file`, never through a work tree, attributes or text conversion. **S8. Scripts that refuse a bare name (SEC-D).** Bash runs `bash NAME` from the current folder when `./NAME` exists, and otherwise from the first match on PATH, and `$0` stays bare either way; `bash --posix` (macOS `sh`) searches PATH too, dash does not (bash manual [D]; F12; F16). So the eight scripts that locate their own folder this way all change their `*)` branch: `method/scripts/method/{done-check,run-checks,status,review-packet,report-check,mutate-changed,setup-write}.sh` and `scripts/release/sync.sh`. The new branch:
- uses `.` only when `$0` and the file bash opened (`BASH_SOURCE[0]`) are both the script's own name and `./NAME` is a file;
- otherwise prints one line, with `printf '%s\n'`, and exits 2: "NAME was started by a bare name found on PATH, or not as a file of its own; run it by its path, such as bash path/to/NAME", with NAME the script's own name written into the line and `$0` not repeated. Done-check keeps its NOT READY could-not-check form, and report-check its FAIL form. Exit 2 is each script's existing bad-usage or could-not-run code [R].

Changed while 8.3 was built, after two adversarial review passes (each finding reproduced in a scratch copy by a second agent before it was acted on). The first form, `./NAME` being a file, let a sourced or piped script run the current folder's `lib/` when that folder held a file named `bash` (then `$0`), and took a path written with backslashes (Git Bash) for the current folder; the own-name check closes both. A caller that chose `$0` itself (`bash -c '. NAME' NAME` beside a decoy `./NAME`) still got through, and `BASH_SOURCE[0]`, which bash 5.2 gives as the full path for a file it found on PATH or sourced through it and leaves unset for `bash -s`, closes that; what bash 3.2 puts there is not measured (A27), and its worst case is the own-name check alone. `$0` repeated in the line let a newline in it forge the line after. sync.sh's `cd` gains `--`.

`cd scripts/method && bash status.sh` keeps working. The three hooks are left as they are: Claude Code always starts them by their full path (A68 (1); the harness proves it). `live-write.sh` is sourced, not run, so `$0` is not its own. The eight blocks cannot share code, since a script cannot find a shared file before it finds its folder. M163's home is `tests/wrappers.test.sh`, which finds every `method/scripts/method/*.sh` and `scripts/release/sync.sh` holding `case "$0"`, fails when it finds fewer than eight, and runs the bare-name case on each. That tests what each script does, not its text, so the blocks may differ in the refusal form and the name. Rejected: a lint holding the blocks to one text (they cannot be one text, and it would read the root installed copies, which keep v0.7.0's `here=.` until step 9's re-sync; section 5). Git Bash and bash 3.2 follow the same documented lookup. They are not run here (A27).
